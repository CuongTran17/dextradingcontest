# Solana Contest Join and NFT Certificate Design

## Goal

Add a Solana-based Web3 layer for contest participation and top-10 NFT certificates. Users join a contest by signing an on-chain Solana transaction. After backend settlement, eligible top-10 users can mint a certificate NFT whose metadata and certificate image are generated by the backend and uploaded to Pinata/IPFS.

## Scope

This MVP does not include token rewards, payouts, trading logic on-chain, or zk/social embedded wallets. Trading and settlement remain backend-owned. Solana is used for participation proof and NFT certificate ownership.

## User Flow

1. User connects a Solana wallet in the frontend.
2. User clicks Join Contest.
3. Frontend sends a `join_contest(contest_id)` transaction to the Solana program.
4. Frontend sends the transaction signature and wallet address to backend.
5. Backend verifies the transaction and stores the wallet on the contest participant.
6. Contest runs normally in the simulator.
7. Backend settlement computes final ranking and snapshot hash.
8. Backend exports top-10 certificate payloads.
9. Backend renders a certificate image for each top-10 user with contest name, rank, recipient name, final equity, ROI, and snapshot hash.
10. Backend uploads each certificate image to Pinata.
11. Backend creates NFT metadata JSON pointing to the image IPFS URI and uploads metadata to Pinata.
12. Admin publishes the certificate Merkle root and settlement snapshot hash to the Solana program.
13. Eligible user claims/mints certificate NFT using proof from backend.

## Solana Program

Use Anchor/Rust.

Accounts:

- `ContestState` PDA:
  - `contest_id`
  - `admin`
  - `join_enabled`
  - `certificate_root`
  - `snapshot_hash`
  - `bump`
- `Participant` PDA:
  - seeds: `["participant", contest_id, wallet]`
  - `contest`
  - `wallet`
  - `joined_at`
  - `bump`
- `CertificateClaim` PDA:
  - seeds: `["certificate", contest_id, wallet]`
  - `contest`
  - `wallet`
  - `rank`
  - `mint`
  - `claimed_at`
  - `bump`

Instructions:

- `initialize_contest(contest_id)`
- `set_join_enabled(contest_id, enabled)`
- `join_contest(contest_id)`
- `publish_certificate_root(contest_id, root, snapshot_hash)`
- `claim_certificate(contest_id, rank, metadata_uri, snapshot_hash, proof)`

The program verifies the Merkle proof for certificate claims and prevents duplicate joins/mints.

## Backend

Add wallet fields to contest participants:

- `wallet_address`
- `wallet_type`
- `join_tx_signature`
- `joined_onchain_at`

Add certificate fields or a certificate table:

- `contest_id`
- `participant_id`
- `wallet_address`
- `rank`
- `recipient_name`
- `final_equity`
- `roi`
- `snapshot_hash`
- `certificate_image_uri`
- `certificate_metadata_uri`
- `merkle_leaf`
- `merkle_proof_json`
- `mint_address`
- `mint_tx_signature`
- `claimed_at`

Backend APIs:

- `GET /api/crypto/contests/{contest_id}/wallet`
- `POST /api/crypto/contests/{contest_id}/join/confirm`
- `POST /api/admin/crypto/contests/{contest_id}/certificates/export`
- `POST /api/admin/crypto/contests/{contest_id}/certificates/publish`
- `GET /api/crypto/contests/{contest_id}/certificates/me`
- `POST /api/crypto/contests/{contest_id}/certificates/claim/confirm`

## Certificate Image and Metadata

The backend renders one image per eligible participant. Image content:

- App/brand name
- Contest title
- Rank, e.g. `Top 1`, `Top 2`
- Recipient display name
- Wallet short address
- Final equity
- ROI
- Settlement date
- Snapshot hash short form

Preferred renderer for MVP: SVG template rendered server-side, then converted to PNG. PNG is preferred over JPG for crisp text. JPG export can be supported later if needed.

Pinata upload order:

1. Render certificate image.
2. Upload image to Pinata and receive `ipfs://...` image URI.
3. Create NFT metadata JSON:

```json
{
  "name": "Crypto DEX Trading Contest - Top 1 Certificate",
  "symbol": "CDTC",
  "description": "Certificate awarded for ranking Top 1 in Summer Cup.",
  "image": "ipfs://...",
  "attributes": [
    { "trait_type": "Contest", "value": "Summer Cup" },
    { "trait_type": "Rank", "value": "Top 1" },
    { "trait_type": "Recipient", "value": "Alice" },
    { "trait_type": "Final Equity", "value": "12850.42 USDT_TEST" },
    { "trait_type": "ROI", "value": "28.5042%" },
    { "trait_type": "Snapshot Hash", "value": "abc123..." }
  ]
}
```

4. Upload metadata JSON to Pinata and store metadata URI.

Merkle leaf:

```text
hash(contest_id, wallet_address, rank, metadata_uri, snapshot_hash)
```

## Frontend

Use Solana wallet adapter for Phantom, Solflare, and Backpack. The frontend handles wallet connect, join transaction, certificate eligibility display, and mint transaction.

## Testnet Faucet

Faucet is optional and can be implemented after wallet join. It is backend-only, uses a dedicated testnet wallet, and does not require a smart contract.

## Acceptance Criteria

- A user cannot join the same contest twice on-chain.
- Backend locks the wallet address for that contest after join confirmation.
- Settlement export generates certificate image URI and metadata URI for each top-10 eligible wallet.
- Merkle root is deterministic from certificate payloads.
- Certificate claim cannot mint twice for the same wallet and contest.
- Certificate metadata points to the generated certificate image.
